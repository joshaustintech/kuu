# Phases 11-16

Orchestration note: when this phase is requested, assess every subtask first, split independent work into concurrent small agents, keep dependent work sequential, and follow the default work loop in `AGENTS.md`.

## Phase 11: CLI And Standalone Lua

Goal:
Match the standalone behavior needed by `main.lua` and manual section 7.

Subtask 11.1 prompt:
```text
Implement the Kuu CLI with Lua-compatible script execution, arg table, -e chunks, -l module loading, -i interactive placeholder, stdin execution, and exit codes.
```

Done when:

- script execution works
- `arg` behavior is tested
- `-e` and stdin execution are tested

Subtask 11.2 prompt:
```text
Implement a minimal Lua-compatible REPL using std::io. Support expression shorthand where required and preserve globals across inputs.
```

Done when:

- REPL smoke tests pass through stdin-driven integration tests

## Phase 12: Full Conformance Loop

Goal:
Close the gap from selected fixtures to the full local suite.

Subtask 12.1 prompt:
```text
Build a test runner command that executes each local Lua 5.5 test file under Kuu, records pass/fail/unsupported, captures logs, and writes a deterministic conformance report.
```

Done when:

- runner handles pass, fail, timeout, and unsupported cases

Subtask 12.2 prompt:
```text
Iteratively fix failures until every pure Lua portion of the local Lua 5.5 suite passes. Add a minimized failing regression test before each fix.
```

Done when:

- all supported upstream tests pass
- each fix starts from a failing regression fixture

Subtask 12.3 prompt:
```text
Evaluate api.lua and C-library-dependent attrib.lua checks. Implement a Rust-native T shim where behavior can be reproduced safely. Mark truly C-ABI and dynamic-library requirements unsupported with exact reasons.
```

Done when:

- every unsupported item has a precise reason
- the conformance report separates language failures from excluded C-ABI behavior

## Phase 13: kuulsp Language Server

Goal:
Expose Kuu diagnostics and source navigation over the Language Server Protocol.

Subtask 13.1 prompt:
```text
Implement the `kuulsp` server transport, startup handshake, shutdown path, and document lifecycle plumbing for open, change, save, and close notifications.
```

Done when:

- the server starts and shuts down cleanly under an LSP client
- diagnostics are published for syntax and resolver errors
- open and change notifications refresh the active document state

Subtask 13.2 prompt:
```text
Wire `kuulsp` to parsed Kuu sources so it can serve hover, go-to-definition, document symbols, and basic completion data from the existing compiler pipeline.
```

Done when:

- language features return stable results for supported fixtures
- requests on stale documents are rejected or refreshed deterministically
- LSP integration tests cover at least one multi-file edit flow

## Phase 14: MCP Server

Goal:
Expose Kuu capabilities through an MCP server for local agent and tooling workflows.

Subtask 14.1 prompt:
```text
Implement the MCP transport and core server bootstrap for `kuu`, including capability advertisement, tool registration, and request routing.
```

Done when:

- the server connects successfully to an MCP client
- advertised capabilities match the implemented tool surface
- invalid requests return structured MCP errors

Subtask 14.2 prompt:
```text
Add MCP tools for parsing, formatting, linting, and fixture execution so external clients can drive the same core functionality that the CLI uses.
```

Done when:

- each tool can be invoked independently through MCP
- tool outputs are deterministic for the same input
- integration tests cover the happy path and a representative failure path

## Phase 15: kuufmt Formatter

Goal:
Provide a deterministic formatter that rewrites Kuu source without changing semantics.

Subtask 15.1 prompt:
```text
Define the `kuufmt` formatting rules, including indentation, line wrapping, spacing, and preservation rules for comments and string literals.
```

Done when:

- formatting rules are documented by tests
- repeated formatting is idempotent
- comments and literal text survive unchanged except for permitted whitespace normalization

Subtask 15.2 prompt:
```text
Implement the formatter and a diff-oriented CLI entrypoint that can format files in place or report pending changes.
```

Done when:

- formatter output is stable across runs
- `--check` style behavior reports unformatted files without rewriting them
- regression tests cover nested blocks, long expressions, and comment placement

## Phase 16: kuulint Linter

Goal:
Provide a deterministic linter that reports actionable diagnostics for Kuu source.

Subtask 16.1 prompt:
```text
Define `kuulint` rules for likely bugs and maintainability issues, including unreachable code, unused bindings, shadowing, and suspicious control flow.
```

Done when:

- each lint rule has a targeted regression test
- rule output includes stable spans and actionable messages
- false positives are minimized on the supported test corpus

Subtask 16.2 prompt:
```text
Implement the `kuulint` CLI so it can lint files, honor configuration, and exit non-zero when findings are present.
```

Done when:

- lint results are reproducible for the same input and configuration
- configuration toggles are covered by integration tests
- the CLI exits successfully on clean files and non-zero on findings
